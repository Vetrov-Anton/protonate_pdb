# protprep — протонирование белка с фиксированными состояниями остатков

[![tests](https://github.com/Vetrov-Anton/protonate_pdb/actions/workflows/ci.yml/badge.svg)](https://github.com/Vetrov-Anton/protonate_pdb/actions/workflows/ci.yml)

Готовит PDB без водородов к `gmx pdb2gmx`: считает локальные pKa через
**PROPKA/PDB2PQR** при заданном pH, но состояния перечисленных вами остатков
задаёт **принудительно**, чего ни PROPKA, ни PDB2PQR сами не позволяют.
Дополнительно умеет то, что PDB2PQR для AMBER делать отказывается: тавтомеры
гистидина, депротонированные TYR/ARG, кэпы ACE/NME/NHE.

> **Силовое поле открывается только на чтение.** Скрипт никогда не пишет и не
> копирует ничего в каталог `*.ff` и не трогает `residuetypes.dat`. Если нужного
> блока в силовом поле нет — работа останавливается с объяснением, и на диск не
> записывается ничего.

## Установка

Одной командой, ничего клонировать не нужно:

```bash
pipx install git+https://github.com/Vetrov-Anton/protonate_pdb.git    # рекомендуется
# или, если pipx нет:
pip install --user git+https://github.com/Vetrov-Anton/protonate_pdb.git
```

После этого в PATH появляется команда `protonate`. Зависимости (`pdb2pqr`,
`propka`, `numpy`) ставятся автоматически; отдельно нужен только GROMACS —
из него берутся силовые поля.

Обновиться: `pipx upgrade protprep`. Удалить: `pipx uninstall protprep`.

<details>
<summary>Если хотите править код у себя</summary>

```bash
git clone https://github.com/Vetrov-Anton/protonate_pdb.git
cd protonate_pdb
./install.sh          # venv рядом с исходниками (editable), команда ./protonate
./install.sh --pipx   # изолированно через pipx
./install.sh --user   # pip install --user
python -m pytest -q   # тесты (нужен установленный GROMACS)
```

Скрипт `./protonate` работает и вовсе без установки: подхватывает локальный
`.venv`, а если его нет — системный python.

## Быстрый старт

Проверка на маленьком примере из репозитория (~1 с; при установке через pipx
подставьте свой PDB или скачайте `examples/fragment.pdb`):

```bash
protonate -f examples/fragment.pdb -o prepared --ph 7.0 \
    --ff amber99sb-ildn --fix A:31:p --fix A:63:HIE
```

Как это выглядит на настоящей структуре:

```bash
protonate -f 6CFO.pdb -o prepared --ph 7.4 --ff amber99sb-ildn \
    --fix A:167:p --fix A:63:HIE --fix B:99:d \
    --nter A:ACE --cter A:NME \
    --run-pdb2gmx
```

Всё то же самое можно положить в файл задания (см. `examples/example_spec.txt`):

```bash
protonate -f 6CFO.pdb -o prepared --spec examples/example_spec.txt --run-pdb2gmx
```

Силовое поле ищется в трёх местах по очереди: по указанному пути, в текущем
каталоге и в установленном GROMACS (`$GMXDATA/top`, `/usr/local/gromacs/...`).
Поэтому `--ff amber99sb-ildn` работает откуда угодно, а `--ff ./my-custom.ff` —
для своего поля. Если поле не найдено, скрипт покажет список доступных.

## Как задавать состояния

`--fix ЦЕПЬ:НОМЕР:СОСТОЯНИЕ` (можно повторять). Вместо цепи можно поставить
`*` — правило применится к остатку с этим номером во всех цепях (удобно для
гомоолигомеров; остатки другого типа пропускаются с предупреждением).

Короткие обозначения: **`p`** = protonated, **`d`** = deprotonated,
**`n`** = neutral, **`c`** = charged. Полные слова тоже работают.

| остаток | `p` (протонирован) | `d` (депротонирован) | `n` | `c` |
|---------|--------------------|----------------------|-----|-----|
| ASP     | `ASH` (COOH)       | `ASP` (COO−)         | `ASH` | `ASP` |
| GLU     | `GLH`              | `GLU`                | `GLH` | `GLU` |
| LYS     | `LYS` (NH3+)       | `LYN` (NH2)          | `LYN` | `LYS` |
| CYS     | `CYS` (SH)         | `CYM` (S−)           | `CYS` | `CYM` |
| TYR     | `TYR` (OH)         | `TYN` (O−)           | `TYR` | `TYN` |
| ARG     | `ARG` (+)          | `ARN` (нейтр.)       | `ARN` | `ARG` |
| HIS     | `HIP` (+)          | `HID`                | `HIE` | `HIP` |

У гистидина буквы заняты тавтомерами: **`d`** = `HID` (протон на ND1),
**`e`** = `HIE` (на NE2), **`p`** = `HIP` (оба, заряжен), `n` = `HIE`.
Прямые имена (`ASH`, `LYN`, `CYM`, `HID`, …) тоже принимаются.
`CYX` — цистеин в дисульфиде (без HG).

## Только выбранные боковые цепи, остальное — по стандартным pKa

Флаг `--standard-pka` (он же `--no-propka`) выключает PROPKA совсем: вы
задаёте состояния нужных боковых цепей через `--fix`, а **все остальные
группы, включая N- и C-концы**, берутся в состоянии, которое им положено при
заданном pH по стандартным pKa свободных аминокислот — без всяких локальных
сдвигов от окружения.

```bash
protonate -f 6CFO.pdb -o prepared --ph 7.0 --standard-pka \
    --fix A:167:p --fix A:63:HIE
```

Таблица (те же значения, что PROPKA использует как точку отсчёта) и результат
при pH 7:

| группа | станд. pKa | состояние при pH 7 |
|--------|-----------:|--------------------|
| ASP    | 3.80  | `ASP` (COO−) |
| GLU    | 4.50  | `GLU` (COO−) |
| HIS    | 6.50  | нейтральный, тавтомер `HID`/`HIE` выбирает pdb2pqr по водородным связям |
| CYS    | 9.00  | `CYS` (SH) |
| TYR    | 10.00 | `TYR` (OH) |
| LYS    | 10.50 | `LYS` (NH3+) |
| ARG    | 12.50 | `ARG` (+) |
| N-конец| 8.00  | `NH3+` |
| C-конец| 3.20  | `COO−` |

Заодно это быстрее (на 6CFO ~1 с против ~11 с) — PROPKA не считается вовсе.
Флаг работает при любом pH, не только 7; если при выбранном pH стандартный
конец цепи должен был бы сменить состояние, а в силовом поле такого варианта
нет, скрипт об этом предупредит (см. ниже про концы). В файле задания то же
самое пишется строкой `pka standard`.

## Водороды только у выбранных остатков

Флаг `--only-fixed-h` (он же `--strip-other-h`) оставляет водороды **только у
остатков из `--fix`** (и у кэпов ACE/NME/NHE, если вы их просили). Все прочие
остатки уходят в файл без водородов — их достроит сам `gmx pdb2gmx`:

```bash
protonate -f 6CFO.pdb -o prepared --ph 7.0 --standard-pka --only-fixed-h \
    --fix A:167:p --fix A:63:HIE --ff amber99sb-ildn
```

Важно: **имена остатков сохраняются**, то есть состояния никуда не деваются —
если PROPKA решила, что Glu263 это `GLH`, остаток так и уедет `GLH`, просто без
водородов, и pdb2gmx построит их по блоку `GLH`. Снимаются именно координаты
водородов, а не решение о протонировании. Хотите, чтобы всё, кроме `--fix`,
было в стандартном состоянии — добавьте `--standard-pka`.

Кристаллическая вода водороды сохраняет (их поставил и оптимизировал PDB2PQR).

Проверено на 6CFO: с флагом и без него pdb2gmx выдаёт **побитово одинаковые
топологии** (различаются только строки-комментарии с путями и датой) и тот же
суммарный заряд; координаты водородов у зафиксированных остатков при этом
совпадают с точностью до символа — pdb2gmx их не трогает, а достраивает только
недостающие.

## Концы цепей

```
--nter A:NH3+ | NH2 | ACE          коротко: p, c = NH3+ ; n, d = NH2
--cter A:COO- | COOH | NME | NHE   коротко: d, c = COO- ; p, n = COOH
```

* `NH3+` / `COO-` — заряженные концы, поведение по умолчанию;
* `ACE` / `NME` / `NHE` — кэпы; строятся геометрически (транс-пептидная связь,
  стандартные длины и углы, поворот метилов подбирается по минимуму контактов),
  водороды кэпа тоже ставятся;
* `NH2` / `COOH` — нейтральные незакрытые концы. **В amber-портах GROMACS их
  нет**: файлы `aminoacids.n.tdb` / `aminoacids.c.tdb` пустые, а тип конца
  задаётся отдельными блоками rtp (`NALA`, `CALA`), нейтральных вариантов среди
  них не бывает. Поэтому такой запрос завершается ошибкой с предложением взять
  кэп. Если вы сами добавили нужные блоки в своё силовое поле, назовите их
  `ZXXX` (нейтральный N-конец) и `JXXX` (нейтральный C-конец, COOH) —
  например `ZALA`, `JALA` — и они будут подхвачены автоматически.

Для нестандартных состояний **на самом конце цепи** (протонированный ASP/GLU и
т.п.) в силовом поле нет ни `NASH`, ни `CASH` — скрипт это ловит и
останавливается, предлагая закрыть конец кэпом.

## Что получается на выходе

В каталоге `-o`:

| файл | что это |
|------|---------|
| `protonated.pdb` | структура с водородами, имена в номенклатуре вашего ff |
| `protonation_report.tsv` | таблица: остаток, pKa PROPKA, итоговое состояние, задано вручную или нет |
| `protonation_report.json` | то же плюс предупреждения и команда pdb2gmx |
| `pdb2gmx.log`, `conf.gro`, `topol.top` | если запускали с `--run-pdb2gmx` |

Дальше — обычный `gmx pdb2gmx`; готовая команда печатается в конце и лежит в
JSON-отчёте. Ключ `-ignh` **не нужен** и нежелателен: имена атомов уже
приведены к rtp, и pdb2gmx берёт наши водороды как есть (видно по строке
«Now there are N residues with M atoms» — число атомов не меняется).

## Как это устроено

1. Из входного PDB берутся стандартные остатки и вода, водороды и altloc≠A
   отбрасываются; лиганды/ионы (`HETATM`) откладываются и возвращаются в конец
   файла нетронутыми (`--drop-het`, `--drop-water` — если не нужны).
2. Запускается PDB2PQR (`--ff=AMBER --ffout=AMBER`) с PROPKA при вашем pH.
   Перед применением pKa словарь подменяется: для зафиксированных остатков
   ставится ±1000, так что нужную форму строит сам PDB2PQR — со своей
   оптимизацией водородных связей и debump'ом. С `--standard-pka` подменяется
   не словарь, а сам расчёт: вместо PROPKA подставляется таблица модельных pKa,
   всё остальное в конвейере не меняется.
3. Что PDB2PQR для AMBER делать отказывается (тавтомер HIS, `TYN`, `ARN`,
   `ASH`/`GLH` на концах), доводится геометрически: протон ставится по
   внутренним координатам (длина/угол/торсион), лишний — снимается.
4. Ставятся кэпы, имена атомов сопоставляются с `*.rtp` вашего силового поля.
   Соответствие выводится из самого rtp (тяжёлые атомы — по элементу, водороды —
   по «родителю» из списка связей), поэтому правки ff скрипт переживает.
5. Финальные проверки — и если что-то не сходится, останов без записи:
   * нет блока rtp для остатка или для его положения в цепи;
   * после сопоставления остались атомы, которых нет в rtp;
   * имя остатка неизвестно `residuetypes.dat` (GROMACS сочтёт его не белком);
   * заряд блока нецелый. Например, `TYN` в этом порте amber имеет −0.399
     вместо −1 — ошибка самого силового поля, чинить её должны вы.

## Ограничения, о которых стоит знать

* **Дисульфиды** по-прежнему определяет pdb2gmx (по расстоянию). Хотите
  зафиксировать — ставьте `CYX` явно.
* **Лиганды.** `A5X`, `MG` и прочие HETATM переносятся как есть, без водородов:
  для них нужны собственные rtp/hdb (в вашем ff уже лежат `TPP.rtp`, `API.rtp`,
  `unl_GMX.rtp` — их достаточность скрипт не проверяет).
* **PROPKA несимметрична.** На гомотетрамере 6CFO цепи B и D получают разные
  состояния (например, B206 → HIE, D206 → HID). Нужна симметрия — фиксируйте
  такие остатки явно через `*`.
* **`TYN` и `ARN` в этом силовом поле использовать нельзя**: их нет в
  `residuetypes.dat`, а у `TYN` вдобавок сломан заряд. Скрипт об этом скажет и
  остановится.
* Вода протонируется PDB2PQR и переименовывается в `HOH`/`OW`/`HW1`/`HW2`.

## Все ключи

```
-f/--pdb            входной PDB
-o/--outdir         каталог результата (по умолчанию prepared)
-n/--name           имя выходного PDB
--ph                pH среды
--standard-pka      не запускать PROPKA: незафиксированные группы (и концы)
                    берутся по стандартным табличным pKa (= --no-propka)
--only-fixed-h      водороды только у остатков из --fix и у кэпов, остальные
                    достроит pdb2gmx (= --strip-other-h)
--ff                силовое поле: путь или просто имя; ищется рядом и в GROMACS
--spec              файл задания (txt или json)
--fix               ЦЕПЬ:НОМЕР:СОСТОЯНИЕ, можно повторять
--nter/--cter       ЦЕПЬ:СОСТОЯНИЕ, можно повторять
--drop-water        выбросить воду
--drop-het          выбросить лиганды и ионы
--no-debump/--no-opt  отключить соответствующие стадии PDB2PQR
--water             модель воды для pdb2gmx (tip3p)
--run-pdb2gmx       сразу проверить результат сборкой топологии
--gmx               путь к gmx (ищется и в /usr/local/gromacs/bin)
```

Коды возврата: `0` — успех, `2` — ошибка в задании/входных данных,
`3` — силовому полю чего-то не хватает (ничего не записано).
